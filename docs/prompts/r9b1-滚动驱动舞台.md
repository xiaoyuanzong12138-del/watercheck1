现在只做一件：在首页问句开场之后，插入一段「滚动驱动」的舞台——往下滑，楼体弹出、水跟着滚动爬升、停在真实层数、解释框滑入；往回滑水会退。

【插入位置】hero 之后、样例体检卡之前。

【结构】
<section class="scrolly">：高度 300vh，position:relative
  内部 <div class="scrolly-stage">：position:sticky; top:0; height:100vh; display:grid; grid-template-columns: 52% 48%
    左：<div class="scrolly-canvas">  ← 必须**复用已有的 buildFloorDiagram**，传入一个 progress 参数控制水位高低，禁止再写第二份 SVG 代码
    右：<div class="scrolly-copy">  ← 旁白 + 解释框

【进度计算】
p = clamp((scrollY − section.offsetTop) / (section.offsetHeight − innerHeight), 0, 1)
用 requestAnimationFrame 节流，p 变化超过 0.002 才重绘；不要用滚动事件直接重排 DOM。

【映射（p 区间 → 画面）】
0.00–0.10：楼体 translateY 60px→0、scale 0.92→1、opacity 0→1
0.10–0.66：水位从 0 线性涨到「供到层数/总层数 × 楼高」（层数实时算，幸福里是 2/6）
0.66–0.74：水位再冲高 0.3 层（碰到楼板），0.74–0.80 回落 0.25 层
0.74–0.80：供到层数以上的楼层 opacity 降到 0.45、轮廓变虚线
0.80–1.00：解释框从右侧滑入（375px 从下方），并用一条 1px 细线连到水面

【旁白（右侧，随 p 切换，淡入上移 10px）】
p < 0.28：`水从楼下的进水管进来`
0.28–0.62：`每上一层楼，就要多 4 米水头`
0.62–0.78：`2 层刚好够`   ← 层数必须是实时值，不是写死
p ≥ 0.78：`再往上，推不动了`

【解释框（p ≥ 0.80 显示）】
标题：`为什么停在这？`
正文四行（数字用页面已有的实时计算结果，不许写死）：
  这栋楼的市政入口水头约 18.0 米。
  每往上多一层，就要多约 4 米。
  6 层要 28 米，现在只有 18 米 —— 差 14.1 米。
  再往上的水，只能靠二次加压。
落款 12px 灰：`依据最小服务水头估算；数据为内置示例`

【硬要求】
1. 不劫持滚动、保留原生惯性，不加 scroll-snap；
2. prefers-reduced-motion: reduce 时跳过 scrub，直接把 p 当作 1（终态）+ 显示解释框；
3. 页签切到后台再回来不重播、不跳动；
4. 375px：画布在上（高 52vh）、旁白在下；整段无横向滚动；sticky 在 iOS Safari 上不错位（用 dvh 兜底）；
5. 帧率 ≥ 45fps（控制台打印一次实测值）；
6. 现有样例卡、示例工程、我的工程、故事卡全部保留不动。

【验收】
□ 下滑到该段：楼体从下方升起（不是突然出现）
□ 水随滚动上涨，**往回滑会退**
□ 涨到 2 层后先冲一下再回落，肉眼可辨

□ 解释框里的数字与报告页一致（18.0 / 28 / 14.1）
□ 375px 无横向滚动、sticky 不错位
□ 控制台打印的帧率 ≥ 45fps
□ prefers-reduced-motion 下直接显示终态
